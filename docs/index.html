01设计理念

开源的助手类 harness，核心理念：为用户提供最简单的交互方案。能力越复杂，落到用户手里的越要简单。

ezharness 认为一个 harness 只需做好三件事：

支柱关注点
上下文工程什么进上下文、何时折叠、如何让模型始终知道自己是谁、在哪、用户最近干了什么
工具封装把系统能力（文件、终端、画板、MCP…）封装成安全可控、即取即用的工具
产品交互方案设计人机协同的交互面：决策、通知、共享终端——对话之外的通道

与 ezloop 的分工

ezloop 是精简的 agent loop 框架，只负责核心循环；ezharness 在其上做产品化的 harness 层。

1
对话不是唯一的通道
决策、观察、操作各有专门的产品面；对话流只承载自然语言。通知全局可达，数据不绑视图。
2

3

零配置可启动、文件夹即存储、桌面窗口与浏览器同一份页面、agent 需要人时跨分支把通知送到眼前。

02快速开始

从 Releases 下载，两种方式任选其一——exe 在哪运行，配置与数据就在哪生成。

方式一：绿色版 推荐

安装步骤
# 1. 下载 ezharness.exe，放入任意文件夹（如 D:\ezharness）
# 2. 将该文件夹加入 PATH 环境变量
# 3. 任意终端输入：
$ ezharness
# 首次运行在同目录自动生成 ezharness.json 与 data\ —— 零配置可用

方式二：安装包 installer

下载安装包双击运行，按引导选择安装目录，自动创建开始菜单与桌面快捷方式，可选「添加到 PATH」。user 作用域安装，无 UAC 弹窗。

首次使用

  • 启动后到「模型」页填 apiKey 即可对话（OpenAI 兼容接口通用）
  • 四槽模型单选：main / vision / image / audio，各自带用量统计
  • 默认监听 127.0.0.1:5260（不触发防火墙弹窗），设置页可改

纯 server 形态（无窗口）

server-mode
$ set EZHARNESS_NO_WINDOW=1 && ezharness
# 浏览器访问 http://127.0.0.1:5260 —— 与桌面窗口同一份页面

03详细介绍 · 树状会话管理

会话数据组织成一颗树：节点是 session（一次换代内的完整对话库），线是用户视角的「会话」。树对用户只露两个操作：分叉（fork）与归档（compact）。

概念含义载体
session（节点）一次换代内的消息库 + 系统上下文sessions/<id>/session.json
线（branch）叶节点到根的 compress 链，用户视角的一个会话topics.json 索引
RootID线根 ID，稳定不变。前端路由、SSE 订阅键、注册表键Session.RootID
叶 ID当前叶 session ID，compact 换代时更新TopicEntry.LeafID

    S1 -- "fork（copy 语义）<br/>从消息 ③ 分叉开新线" --> S3["S₃ · 新线<br/>RootID = S₃"]:::fork
    S1 -- "compress（compact 换代）<br/>摘要封存 · 空库新 system" --> S2["S₂ · 新一代<br/>同一条线 · 叶更新"]:::gen2

    S2 -. "上翻懒加载<br/>沿 compress 链拉旧世代" .-> S1

左：fork 拷贝前缀开新线（删源不伤分叉）；右：compact 归档换代（同一条线，旧库封存只读，新库带摘要继续）。

compact 归档换代的四步

  1. 摘要：摘要模型生成前情摘要（2 分钟预算，期间原子锁：锁发消息、锁切分支、防二次触发）
  2. 封存：旧库标记 Archived=true，内容不动
  3. 写新库：空 messages + 新 system（base 全量重载 + 摘要段 + 旧库路径引用），compress 边指回旧库
  4. 热切换：内存换 system、换叶；线索引换叶不换线——前端无感

切换与并发

  • 切线先查注册表，命中直接激活——后台分支的运行轮不取消，线间可并发，切回时重建现场
  • 启动按 mtime 取最近未封存快照恢复；删除清整条线的全部世代，运行中拒绝
三种「分叉」勿混淆：① fork 分叉（copy 语义，复制前缀开新线）；② fork 分身（task 子循环，事件带 ForkID，存档在 forks/ 下只存增量，前端分身抽屉展示）；③ compact 换代（归档封存，同线换叶）。 trim 是模型侧上下文整理（就地折叠不换库），archive 是用户侧会话树管理（换代封存）。

04详细介绍 · 上下文工程

一条线同一时刻只有一个活跃上下文（system + 消息库视图）。让模型始终知道自己是谁、在哪、用户最近干了什么。

system prompt 两段式组装

每 session 创建时组装一次并固定（重启从快照还原不重组；skill / mcp / 记忆变更下个 session 生效）。

trim 压缩：两条触发路径

路径机制
水位自动PromptTokens > 窗口 × TrimPercent%（默认 75，0 禁用），轮末统一执行
模型主动trim_context 工具：轮内只登记 pending，轮末执行——模型觉得该整理就整理

执行：摘要折叠段（独立 2 分钟预算）→ 截断为 [head, tail, marker]（保留末 4 条；孤儿 tool 前移保证配对完整）→ 尾插 marker。fork 只折叠分叉点之后的增量。

追加式档案不变量：折叠段挂 Metadata，视图起点回溯与全量合并是 modelView、落盘、收尾三处共用的同一套判断—— marker 前的档案从未进过本轮视图的必须保留，跨轮覆盖不丢档。

agent_status：轮首快照注入

不是状态机枚举，是逐轮注入的快照记录——system 每 session 固定，轮内资源变更靠这条告知模型。

  • 每轮开始、用户输入前插一条 <agent_status>：当前时间、距上次输出分钟数、上下文水位、是否建议 compact、资源变更清单
  • 终端变更细分新增（报来源 用户/AI）/ 已退出 / 已修改 / 已关闭——用户手敲了什么 agent 知道
  • 同时发 SSE 事件供前端状态卡与水位条；轮停止原因映射中文分类
兜底双保险：guard 按窗口余量动态卸载放不下的工具结果到 .ezloop/offload/（小结果豁免，写入失败硬截断）—— trim 没来得及跑也不会溢出。

05详细介绍 · 人机交互设计

agent 的能力边界再大，落到用户手里的只是几个交互面。ezharness 把人机协同交互工具外置——不塞进对话流硬凑，做成独立的产品面，让用户在 agent 工作时能看、能改、能答。

决策链路：四档审批策略

档位行为
ask 每次审批所有工具调用都出决策卡等用户
black 黑名单名单内的出决策卡，其余放行
white 白名单名单内的放行，其余出决策卡
auto 全部免审全自动（人机与内部工具恒免审不受档位影响）
  • 审批 / 询问两型 DecisionCard 嵌在时间线，设置页即时生效
  • 悬置请求登记 pending——断线重连可重放；刷新后由 decisions.jsonl 重建
  • 轮已结束的过期决策自动丢弃

全局通知栏：跨分支找到你

  • 汇总所有分支（含后台分支与分身）的未决请求——无论用户停在哪个分支哪个页面，agent 需要人时一定能找到人
  • 通知内联直接决策（乐观移除）；「查看」跳转：跨分支先切线，分身请求开分身抽屉定位决策卡
  • 服务端为唯一真相，内容不变不换引用，防前端抖动

06架构与构建

一次构建产出一个自包含的 exe，放到哪里都能跑，数据就地在哪。没有 dev server、没有热重载、没有环境变量开关——开发与发布走同一条路径。

桌面窗口与浏览器访问的是同一份页面、同一个服务——行为完全一致。
  • 后端 Go + gin，三层 MVC（controller → service → domain）；前端 Svelte 5 + Vite + TypeScript
  • 通信 REST + SSE（事件流）+ WebSocket（终端）
  • 前端恒内嵌单二进制（dist 缺失编译直接报错），无 dev server

应用根与数据目录

data-layout
D:\ezharness\              # 应用根 = exe 所在目录
├─ ezharness.exe
├─ ezharness.json          # 结构配置：port / listen / dataDir / 窗口尺寸
└─ data\                   # 数据目录（可配置）
   ├─ models.json          # 四槽模型
   ├─ settings.json        # 设置（含 trim 水位）
   ├─ toolRules.json       # 四档审批规则
   ├─ sessions\            # 会话树（session.json · forks/）
   ├─ topics.json          # 线索引
   ├─ memory\              # 长期记忆
   ├─ workspace\  apps\  .ezloop\

零配置可启动：缺失自动创建默认（端口 5260、监听 127.0.0.1、数据目录 data/）；损坏备份 .bak 重建。启动即 chdir 到数据目录，进程 cwd 即数据目录。

开发与发布

script
script\dev.bat            # 开发调试：npm run build -> go build -> 启动 exe
script\release.bat        # 发布：wails3 task package -> ezharness.exe + installer.exe
  • 前置依赖：Go、Node.js；出安装包另需 wails3 CLI 与 NSIS
  • 开发数据落在 build/dist/，与产品行为（数据在 exe 旁）完全一致
  • 设置页改端口 / 数据目录后进程内换代重启：收尾运行轮落盘 → chdir → 重建，前端凭代际计数判断新服务就绪
  • NSIS 默认 user 作用域（无 UAC）；per-machine 包加 INSTALL_SCOPE=machine
